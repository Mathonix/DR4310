# DR4310 网页上位机 UI/UX 设计实施方案

## 1. 范围与评审依据

本次仅交付本文件，不修改源码、测试、截图或构建产物。以下是后续实施方案，不代表功能已实现或已通过测试。

已阅读 `src/page.ts`、`src/base-css.ts`、`src/console-css.ts`、`src/dashboard.ts`、`src/gauge.ts`、`src/chart.ts`，以及 `src/client.ts`、`src/uartcfg.ts` 的页面绑定、动态文案、参数渲染与安全路径，并核对 `src/auto-enable.ts` 和现有浏览器检查。已查看 `screenshots/bootae-desktop-dark.png`、`bootae-desktop-light.png`、`bootae-mobile.png`、`bootae-settings.png`、`bootae-settings-mobile.png`、`simple-desktop-dark.png`、`simple-desktop-light.png`、`simple-mobile.png`。

截图用于视觉判断，交互以当前源码为准：`simple-*` 中的运行时自动使能开关已不在当前页面；当前 `dAe` 是只读指示，只有配置页的 `bootAe` 设置上电行为。不能照旧截图恢复运行时开关。调试页问题主要由当前 HTML/CSS 结构推断，后续须补充两端实机布局验收。

DR4310 是直驱电机。只保留现有 Kt 力矩换算，不增加减速比、传动比、输出轴或相关设置、计算及文案入口。

## 2. 现状问题与调整方向

| 维度 | 桌面现状 | 手机现状 | 执行动作 |
| --- | --- | --- | --- |
| 布局层级 | 仪表盘的状态在左、目标和启停在右，空白较大；配置页先出现安全、连接两块，再进入参数任务；调试页先排四张图，操作区与故障详情在后 | `.dash` 单列后仍先渲染 `.dleft`，大表盘领先于输入、启停；连接标签与 ID 下拉分离 | 状态汇总前置；手机输入和启停在表盘前；配置工具条贴近参数；调试操作导航在图表前 |

| 颜色 | 强调色同时用于连接、设定、启动、读取、同步、运行状态；亮色主题浅青、灰字、彩色曲线需复核对比度 | 实测指针半透明且细，目标/警告都用琥珀色；不能仅凭颜色辨认状态 | 成功与强调分工；目标色独立 token；实测不降透明度；状态配文字，目标/实测配图例 |
| 按钮优先级 | 配置页“读取”“同步”同为实心；仪表盘“断开”与“启动”争夺焦点；“重置”混在高频操作里 | 操作条任意折成两行；急停及 toast 在截图中覆盖目标、参数输入区域 | 每个任务组一个主操作；读取/设定/断开为次级，启停优先；重置移至“更多操作”；设置急停避让区域 |
| 信息密度 | 仪表盘偏松、参数表偏密；调试区一次铺开多个控制协议、增益、十六进制与在线参数 | `.params { min-width:460px }`，窄屏必须横滑；子导航的“其他”孤立换行；四张图推迟操作 | 仪表盘收紧；参数表手机改为同 DOM 的行式编辑；子导航单行横滑；调试技术细节默认折叠 |
| 文案统一性 | “设置/参数配置”“归零/设零”“清故障”“刷新 INFO”“保存到 Flash（SAVE）”混用；动态文本含 raw、latched、Vbus、AM/PM | 长连接 toast 跨行遮挡；实时发送复选框说明过长；中文、命令、单位连续拼接难扫读 | 中文动作优先，协议名、单位保留；非关键说明进 title；危险后果、单位、未保存状态仍可见 |

另有状态解释问题：`bootae-*` 显示设备“运行”同时按钮为“启动”。这可能是设备上电运行、上位机尚未建立控制会话，并非可仅靠改色修复的矛盾。状态标签明确为“电机运行”，启停按钮继续反映现有会话；title 解释两者区别，不能擅自把 `dStart` 改成依据设备反馈发送另一种命令。

## 3. 布局规则与六个目标线框

### 3.1 共用规则

- 桌面断点为宽度 ≥1024 px；768–1023 px 为紧凑单列；≤767 px 为手机布局。最大内容宽 1200 px，桌面页边距 24 px，手机 12 px。以下尺寸均为 CSS px。
- 头部桌面高 64 px；手机为品牌/主题和视图导航两行，每行交互高 44 px。三视图名称统一为“仪表盘 / 参数配置 / 调试”。不新增底部导航。
- 原 `.connection-bar` 移到三个 `.view` 之外、仍在 `.work` 中，成为共用连接条；同一个 `motorId`、`dLink`、`dConnect`、`dRoute` 服务三视图。手机第一行链路、连接、简短状态；第二行完整的“电机 ID + 下拉”，不拆标签。
- 原 `.dbadges` 同样移到视图外，作为共用状态行，保留 `dStatus`、`dStatusT`、`dFault`、`dAe`。正常时紧凑，故障时允许换行。只展示已有状态，不推断未知设备已失能。故障代码不可截断或仅藏在 title。
- 页面全程保留固定急停；连接断开、页面切换、输入聚焦、故障、未连接时均不禁用。急停不放进任何 view、details 或普通操作菜单。
- 表盘、目标、四模式、启停在仪表盘完整保留；其他视图通过顶部一个点击返回仪表盘，不复制运动控制控件。调试原有发送、启停控件也全部保留。

## 4. 卡片、排版与主题规范

### 4.1 组件规格

| 项目 | 桌面 | 手机 |

### 4.3 按钮与浮层

- 仪表盘：启停为主操作，设定为描边次级；连接仅在未连接时强调，断开为次级。模式选中使用浅强调底，不能看起来像四个主提交按钮。

## 5. 文案替换及术语规则

### 5.1 统一术语

- **启动 / 停止**：仪表盘控制会话按钮，继续对应现有 start/stop；启动不能简单重命名为“使能”，停止也不等同于急停。
- **使能 / 失能**：仅描述驱动功率级的已知状态或具体底层动作；不把“空闲”“无反馈”猜成“已失能”。“自动使能：开/关”用于只读运行状态，“上电自动使能”用于配置开关。
- **急停**：只用于紧急停机路径及 Esc，不用于暂停图表、停止波形、清故障或普通 STOP 快捷按钮。
- **同步**：写入全部修改项并保存到 Flash；不得用于“读取”、实时数据刷新、单项 RAM 写入或刷新 INFO。
- **重置**：仅指固件 DEFAULTS 恢复默认参数，当前仅 RAM，需同步持久化。目标置零叫“目标归零”，当前位置建零点叫“位置设零”，输入恢复叫“撤销输入/默认输入”。
- **清除故障**：仅清故障，不能叫“重置”，不能暗示电机会启动。
- 标签尽量 2–6 个汉字；“上电自动使能”允许 6 字，MIT/CAN/Kp/Ki/Kd 和物理单位为必要技术术语。协议原始帧、日志原文、自定义命令不翻译，不改变大小写。

## 6. 不变量与禁止事项

1. **通信与命令不变**：CAN 标识符、帧格式、编码、限值、串口波特率、换行、命令字符串、参数键、固件能力判断、发送频率与路由优先级全部保持。HTML 可见文本与命令数据分离；尤其 `data-u="STOP/RUN/ZERO/CLEAR"`、所有 option value、`data-mode/data-dmode/data-page/data-tab/data-set` 不改。
2. **全部标识不变**：所有现有元素 `id` 与 `data-testid` 的值及唯一性不得改变，包含动态生成的 `cfgBody_*`、`pr_*`、`pd_*`、`pv_*`、`pg_*`、`uv*` 等实际存在的标识。不得以“视觉隐藏”为由删除节点；仅新增无冲突布局 class/无障碍属性。移动节点前核对祖先选择器、事件委托与 `closest()` 依赖。既有 testid 保留在原功能节点，不能挪给占位元素。
3. **急停不变**：浮动 `estop` 与全局 Esc 始终调用现有急停路径；无额外确认、无禁用、无被菜单遮挡。普通停止不能替换急停。取消所有周期发送、波形、待发命令及异步控制会话的先后顺序保持。
4. **停机先关闭自动使能**：保持 `stopCanWithAe` 先发送关闭 AE 再失能/急停；急停 CAN 连发两次；串口先 `AE 0` 再 `STOP`，AE 失败也继续 STOP，不能等待 AE 应答而延迟 STOP。保持 GM 零帧和所有链路停机逻辑。
5. **看门狗不变**：`visibilitychange` 先停波形，`wdHidden` 开启时停机；`pagehide` 同原条件；默认勾选保持。故障、反馈丢失、断开连接、节点/模式/链路切换的停机、反馈时效和控制取消逻辑不变。上电已自动运行也继续受现有反馈看门狗覆盖。
6. **位置/MIT 对齐不变**：启动先使用同链路同节点的有效当前位置；现有扩量程、硬上限、未知位置确认、调试路径对齐均保持。不以美化或保存输入为由绕过对齐。
7. **波形不变**：保留幅值、偏置、频率和最终发送限幅；`|偏置|+幅值≤量程`、硬件范围及各模式频率限制保持。停止波形恢复目标的行为不变。
8. **上电自动使能确认不变**：`bootAe` 开启时以及写入路径的现有确认均保留；包含模式、目标、单位、同步保存和重启生效后果。`BOOT_*` 代理/隐藏参数绑定保持，`dAe` 不改成运行开关。
9. **数据语义不变**：无反馈继续显示“—”，不能补 0 或假值；区分当前故障、锁存故障、历史快照。电流关键读数仍为 A，力矩目标仅在有效 Kt 时用 N·m；位置用现有 rad，机械角图保持 °。保留原数据精度、缓存、导入导出及采样行为。
10. **直驱边界不变**：不新增或显露减速比功能；源码里已有隐藏兼容字段保持隐藏，不借参数表重排恢复入口，也不新增对应导入导出项目。

- 仪表盘：四模式可用性保持原固件规则；手机 `dTarget` 和 `dStart` 的 DOM/可视顺序均在 `dGauge` 前；MIT 四附加字段齐全；读数和故障不因折叠隐藏。
- 参数页：电机/驱动/通信/存储/其他逐页检查；上电行为开关可聚焦且取消确认后回退；320 px 不必横滑才能编辑或写入；当前值、新值、单位范围与修改状态完整可读。
- 调试：原生、GM、串口、日志全流程可访问；展开/收起不取消或偷偷启动发送；曲线暂停、数据记录停止和电机停止语义区分；重新展开 canvas 正确绘制。
- 安全：浮动急停与 Esc、页面隐藏、故障、丢反馈、启动中急停、节点切换、停机先关 AE、位置/MIT 对齐、波形限幅、BOOT_AE 确认沿用现有模拟设备测试；核对线上帧/命令顺序，不仅看按钮文字。
- 状态：未连接、有连接无反馈、正常运行、上电自动运行但无上位机会话、故障、锁存故障、未知 AE、旧固件功能受限分别检查；不能把“已发送停机”渲染为未经反馈确认的“已安全停机”。
- 标识：源码静态节点和运行时动态参数节点分别核对；原 id/testid 不缺失、不改值、不重复，所有监听器仍绑定真实控件。
- 后续实施时执行 `npm run typecheck`、`npm test`、`npm run build:client`，再使用仓库现有 `scripts/preview.mjs` 和 `test/e2e/checks.mjs` 的模拟设备流程。视觉检查不能替代命令/安全回归；本次仅文档交付，不声称这些验证已运行。
