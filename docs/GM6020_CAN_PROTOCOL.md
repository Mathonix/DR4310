# GM6020 风格 CAN 电流控制协议

## 兼容范围
参考项目提供的《RoboMaster GM6020直流无刷电机使用说明20231013》。支持电流命令和反馈，不是完整原厂固件替代。电压命令 0x1FF / 0x2FF 不执行。

Classic CAN，1 Mbps，标准数据帧，DLC=8，多字节字段大端。扩展帧、远程帧、错误长度不作为控制命令。

| 电机 ID | 电流命令 ID | 本机字节（从 0 计） | 反馈 ID |
|---|---|---|---|
| 1 | 0x1FE | 0–1 | 0x205 |
| 2 | 0x1FE | 2–3 | 0x206 |
| 3 | 0x1FE | 4–5 | 0x207 |
| 4 | 0x1FE | 6–7 | 0x208 |
| 5 | 0x2FE | 0–1 | 0x209 |
| 6 | 0x2FE | 2–3 | 0x20A |
| 7 | 0x2FE | 4–5 | 0x20B |

电流命令为有符号 int16，±16384 对应 ±3 A：`raw = round(Iq_A * 16384 / 3)`。线上量程不等于实际允许电流：当前项目工作 Iq 限幅为 2.5 A，瞬时相电流过流保护仍为 3.5 A。下方小电流运行记录不代表已验证 2.5 A 满载运行。

## 使能与停机（项目安全扩展）
1. 上电保持关闭。先发送本机槽位为零的电流帧，建立启动准备状态。
2. 再发送非零目标电流，安全条件满足且当前空闲时，进入电流环并使能功率级。
3. 建议每 10 ms 刷新。活动会话连续 100 ms 无有效本机电流帧，软件关闭功率级并取消启动准备。
4. 本机零电流命令关闭当前 CAN 会话的功率级，同时准备接受下一条非零命令。
5. 超时、旧 STOP 或安全联锁取消会话后，持续非零帧不能重新启动，必须重新发送零帧。不自动清除故障。
6. 不抢占其他活动控制模式。旧协议接管时取消 GM 会话；GM 超时不适用于旧协议拥有的运行模式。

零命令是关闭功率级，不是使能状态下保持零力矩；这与原厂行为未必相同。失能不等于机械刹车，转子可继续滑行。

ID=2 示例（其他槽位置零，仅用于确认不会误控其他电机的台架）：
```text
标准帧 ID=0x1FE DLC=8
准备 / 停机：00 00 00 00 00 00 00 00
+0.1 A：     00 00 02 22 00 00 00 00
-0.1 A：     00 00 FD DE 00 00 00 00
```
保留旧 STOP：标准帧 `0x100 + ID`，8 字节全零。ID=2 时为 `0x102`。旧状态帧 `0x180 + ID` 约 10 Hz。

## 反馈
周期约 1 ms，标识符 `0x204 + ID`。

| 字节 | 数据 |
|---|---|
| 0–1 | uint16 机械角度 0..8191；度数 = raw × 360 / 8192 |
| 2–3 | int16 转速 rpm |
| 4–5 | int16 实际 Iq；项目约定 Iq_A = raw × 3 / 16384 |
| 6 | 0xFF，温度不可用，不是实测 255°C |
| 7 | 0，保留 |

手册未明确反馈电流比例，本项目采用命令的比例，不应据此推断原厂比例。温度哨兵也是项目扩展。空闲时反馈电流置零，避免发送失能前残留的 FOC 值；此时的零不是独立电流测量结果。

## 编译与烧录
```powershell
# 仅编译指定 ID
python tools/build_flash_motor.py --motor-id 2
# 编译、SWD 烧录、逐段校验，检查复位后驱动关闭
python tools/build_flash_motor.py --motor-id 2 --flash
```
ID 仅允许 1..7，固化在 Flash 中，不能靠 RAM 改值切换。也可使用 `cmake --preset Release -DMOTOR_CAN_ID=2` 后编译。默认 ID 为 2。

烧录脚本不发送运行指令。清单：`build/Release/4310_G431KBT6.manifest.json`，含 ID、CAN 标识符、ELF SHA256 和 Flash 校验结果。烧录前保持停止，不要让其他主机同时控制电机。

## PCAN 验证
需要独立单电机台架、PCAN_USBBUS1、python-can，以及烧录用 J-Link。
```powershell
# 不主动启动电机
python tools/pcan_gm6020_test.py --motor-id 2
# 允许短时小电流转动
python tools/pcan_gm6020_test.py --motor-id 2 --run
```
脚本设置 600 rpm / 1.5 A 观测中止阈值，不替代固件保护或硬件急停。电流模式不控制转速，空载也可能快速加速，勿触碰转子。

### 2026-09-16 实机复测
当前已烧录并校验 ID=2，反馈 0x206。活动测试日志：`logs/pcan_gm6020_id2_20260916_223756.json`。

- 反馈约 1 kHz：启动队列窗口约 1002 Hz，其余阶段约 999.9–1000.9 Hz。
- 0.05 A / 2 s，转速 0..231 rpm。
- 0.10 A / 150 ms，转速 0..343 rpm；随后滑行阶段峰值约 348 rpm。
- 错误槽位、电压帧、错误组、扩展帧、短帧、远程帧未启动电机。
- 超时停机、非零流不能重启、零帧后重新启动、零命令停机、旧 STOP 阻止非零流重启均通过。
- 所有接收到的旧状态帧故障字段为 0，最终空闲、转速 0。
- 超时设定是 100 ms；测试通过 10 Hz 状态帧在 0.4 s 窗口确认退出运行，并非精确测量 100 ms 延迟。
- 最终 SWD 25 s / 473 点只读观察：CPU 运行、模式 0、PF0 驱动使能始终为 0、三相占空比均为 0；故障及编码器 DMA 错误为 0。日志：`logs/swd_observe_20260916_224016.json`。

修复了调试器脱离导致 DWT 时钟关闭、转速反馈异常，以及 CAN 错误被动后禁止发送导致不能自行恢复的问题。尚未验证满载、满电流、热稳定性及全工况 PI 性能。
